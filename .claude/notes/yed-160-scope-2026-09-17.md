## Diagnosis
**Dominant cause — structural gap.** Every producer that got wired (`trend_radar`, `morning_refresh`, `inbox_miner`) had the graph as its *only* destination. Both event workflows already had one — Notion — so the graph write was never added. `/post-event-content` Step 3.8 is named "Knowledge-graph write-back" and writes **Notion only**; `/event-deep-research` Step 4 writes Notion + HubSpot and only *reads* the graph at 1.7a. The manifest → `spine_client` writer pattern exists (`inbox_signal_write.py`) and was never generalized to events.

**Systems read: Shifting the Burden.** Notion is the symptomatic fix that satisfies "where do the learnings go?", so the fundamental fix (a graph producer) never gets built and the graph's first-hand-signal capacity atrophies. The 2b migration *masked* it (59 rows read as "the graph is fed"); the hub then codified the mask — the trust strip filters `kind=eq.market` with a comment to exclude attended "so the one-time 2b migration isn't read as a live producer" (*Drifting Goals*, secondary). Ruled out: Fixes that Fail (migration hid the gap, didn't cause it); Tragedy of the Commons (single actor, missing flow); Success to the Successful (no resource contention).

**Staged/HITL rationale:** correct for *claims* (unreviewed transcript ≠ truth; ADR-9), but a **rationalization** for the missing event rows and entity hyperedges — those are facts already reviewed in Notion at research time.

**Sequencing:** YED-81 is Done (09-13, ADR-9 Accepted, guard live) — no longer a block. New hazard: YED-160 says the promotion path can share `/doc-digest` lane A, but **`/doc-digest` does not exist** (YED-157 B3–B5 In Progress).

## The plan
One script, `.claude/scripts/post_event_spine.py`, importing `spine_client` (the only sanctioned write path). No new tables.
- **`ensure-event --manifest m.json`** — upsert the `attended` row + entities + hyperedges from a Notion-derived manifest. Dedup: `notion_page_id` → (title, date, kind). Persons: professional fields only (name · title · company_id · linkedin_url · role_context) — **never bio text from a transcript**. Hyperedge roles: `speaker` / `host` / `tagged_topic`. `--dry-run`.
- **`stage-claims --brief <post_event_brief> --transcript <file>`** — parse **only** the numbered learnings sections (Pro-Tips, Best Practices, Pitfalls, Hot Takes, Substantive Insights, Stat Bank) into `doc_claims` as `candidate`. `document_sha256 = sha256("post_event:" + notion_event_id)`; `claim_key = sha256(normalized claim_text)`; locator carries event_id/section/speaker/timestamp/transcript_sha; quote ≤ 25 words; `confidence = min(HIGH/MED → 0.8/0.6, 0.8)`. Zero extra inference — the brief already exists. **Zero-claim parse warns LOUD.**
- **`promote --event <id> --approve k1,k2`** — PATCH status, POST `event` + `event_entity`, set `promoted_event_id`. Re-run = no-op.

**Open decision — promoted `kind`.** Spec says `attended`; that mints N "attended" rows per real event, corrupts hub semantics, and the trust strip's `kind=eq.market` filter would hide the producer — failing the spec's own acceptance criterion.
- **Option A (recommended, no DDL, ships Friday):** `kind='market'` + `post_event:` source prefix. Visible on the trust strip with zero hub change; re-kind later is one PATCH.
- **Option B:** new `kind='observed'` — one `ALTER … event_kind_enum` in the dashboard (**Alex only; PostgREST can't DDL**) + ADR addendum + hub filter. Batch with YED-157 B4's `reference`-kind addendum.

**Sequence:** Fri = script + PRD · Sat = wire into Step 3.8 + ledger gate · Sun = backfill the 24 absent events **through `ensure-event`** (not a separate script — that's the drift this whole note is about). Claims backfill only where a `post_event_brief` exists: Shortlist Aug, GTM Leaders Vol.1, Daytona Sept, LeadDev, Postgres Tuning. Running `ensure-event` over the 59 `increment_2b_gtm` rows must be a **no-op** — that's the idempotency proof. Postgres Tuning (09-16) is the acceptance run.

**Out of scope:** `/doc-digest`, Gemini extraction, the `observed` DDL, hub changes, relevance recompute (YED-131), HubSpot, a Notion approval surface, re-kinding the 2b rows. **Day-2 fast-follow:** `/event-deep-research` Step 4 calls `ensure-event` at research time — same function, closes the row gap at the source.
