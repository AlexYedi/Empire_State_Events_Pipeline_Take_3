# Substrate vs. backlog reconciliation — run in parallel, with a partition (2026-09-18, Fable)

**Question (Alex):** do the Knowledge Substrate program and the backlog-reconciliation ("home") plan conflict, and should they run in parallel worktrees or in sequence — and if in sequence, which first, judged by *which addresses more gaps, issues and unparked questions*.

**Answer in one paragraph.** Run them **in parallel, in two worktrees, under a hard partition**: the home session is the *only* writer of Linear, `roadmap.md`, `CLAUDE.md`, `linear-convention.md`, memory and `market-intel-spine.md`; the substrate session writes *code and new files only* and hands every Linear/roadmap/memory edit to the home session as a list. Do home **Steps 0–B first** (they are ~35 min of Alex's time, and they give the substrate's five pending decisions a home instead of a fourth notes file). Start substrate **W1 (the review's one-week cut) the same night** — it removes a measured friction on the active path (24 of 27 recent events absent from the graph; `person` frozen since 08-06), so the steering bias says build it now, not after a hygiene pass. Home **Steps C–E** run Sun→Wed and *absorb* the substrate's Linear reshape as part of batch 1, so Linear is touched once. On Alex's literal criterion the home plan "addresses" ~6× more items (it files ~170; the substrate substantively resolves ~10–12 in W1, ~25–30 over four weeks) — but filing is not resolving, and only the substrate closes the largest measured gap. The two are complementary far more than they collide; the one place the home plan *works against* the substrate is its "prioritization only after cleanup" rule, which must not be applied to a build already in motion with a named friction.
