The 45-second pitch

The Funds track says it plainly: LPs commit capital for ten years and get PDFs, and marks move with little explanation. At emerging funds the GP writes that letter by hand from founder emails that come in 40 formats. LPs can't check any of it, and 79% of LPs declined to re-up with at least one GP last year. We're building the layer that reads whatever founders send, pulls every metric with its source, flags anything that changed without an explanation, and drafts the letter only from verified numbers. The LP can click any figure and land on the founder's sentence. Carta traces numbers for the GP; we trace them for the LP. I've built the data set, the answer key and the scorer, so we start coding at 10:30. I need a backend/extraction person, a front-end person and a data/eval person.

Why this, and why it can win

The gap

  • Collecting and extracting portfolio data is crowded (Carta, Visible, Standard Metrics).
  • Nobody owns the GP's "what moved and why" narrative for small funds on AngelList, Sydecar or spreadsheets.
  • ILPA's 2025 templates standardize the fund ledger, which the admin owns. The portfolio narrative stays unstandardized.

The insight

  • The scarce thing for a Fund I is LP trust, not GP hours.
  • A fluent AI letter can hide more. Our letter renders only from reconciled numbers that have sources.
  • Provenance stands in for a track record a new manager doesn't have yet.

Extraction prompt rules (starting point)

  • Return only values that appear in the text. If a value isn't there, return null with the reason "not reported".
  • For every value, copy the exact quote it came from.
  • Keep the founder's currency and units; don't convert.
  • "ARR" counts only if the revenue is recurring. Otherwise flag non_recurring_arr.
  • If the summary and a table disagree, return both and flag conflicting_figures.

One ledger, three layers

  1. Today: the provable update (F1–F4, P1, P2, E1). Every number traces to its source; every change is explained.
  2. Next: path to liquidity (Track 4's secondary-pricing clause, from the seller's side). For each company: exit readiness, likely acquirers (akta.pro company data), and the fund's DPI if it sells now vs. holds. M&A is the primary exit route ($465B, a decade high) and no tool serves a small GP here. Subscription pricing, no success fee, so no broker-dealer licence is needed. Verified numbers in a sale data room should narrow the ~22% opacity discount (a hypothesis).
  3. Feature: LP engagement signals (F4, Fund II re-up). The same facts go to every LP and only the framing is personalised, which avoids selective disclosure. What LPs click shows the GP who will re-up.

Expect the question “why not build a secondaries marketplace?”. Answer: it's crowded, it only reaches late-stage names, and charging a success fee requires a broker-dealer licence. Detail is in liquidity-and-lp-expansion.md.

Judge lens

First 20 seconds to judges: “LPs commit capital for ten years and get PDFs in return. Others build tools to read those PDFs after they arrive. We make the PDF provable before it's sent: every number traces to the founder's own words, every unexplained change is flagged, and the GP approves before an LP sees anything.”

No judge has written about LP reporting. Four point the same way: trust comes from inspection and approval, and value comes from owning a workflow with a measurable outcome, not from model IQ. Lead with the gate, not the model. No rubric is published; the working rule is “business and code count equally.”

Questions to expect

Likely questionOur answer
"How is this different from Tamarix?"Tamarix helps LPs read and reconcile what GPs send. We work upstream, for the GP: founder updates in, a provable report out. The two are complementary, since an LP tool reads a provable report better.
"Isn't this Carta / Standard Metrics / Taghash?"Those tools collect structured KPIs through a portal founders fill in; Carta also stops at tearsheets for its own admin customers. We start from the email founders already send and write the letter, every number sourced. They collect KPIs; we write the letter.
"How do you handle one company held across three funds?"Each number lives once, as a source-linked row. Each fund's report would read that row through its own ownership, so nothing is double-counted or drifts between vehicles. Today's demo is one fund; say this is the design, not the demo. Currency: we keep the founder's currency as reported; a converted view would be a report-time step with the rate and date shown.
"Do the numbers tie out? Who approved what?"Portfolio totals are computed in code from the company rows, never by the model. GP approvals live in the review queue; only claim an audit log if one ships by the 3:30 freeze.
"Why not just run Claude Code on the inbox?" (host)That's the harness Jon Chin says they shouldn't run their back office on. A harness gives you an answer; this gives you a letter where every number is checked, flagged or approved, and an LP can trace it.
"What if the model invents a revenue number?"No span, no number. The quote must match the source text exactly, "not reported" is a valid answer, and nothing ships without GP sign-off.
"Where does our data go?"Names are tokenized before the model call, the GP decides what the LP sees, and a local-model option is on the roadmap.
"How accurate is it?"Scored against a hand-built answer key, shown next to the do-nothing baseline.
"Small market, small ACV?"Emerging managers are the wedge. The same source-linked ledger sells upmarket to LPs and fund-of-funds who need to verify GP claims.
"Would founders hate this?"Founders send what they already send. There's no new form to fill in.
"Won't GPs just switch off the LP links?"For a Fund I raising Fund II, provable numbers are the signal an incumbent's narrative can't fake.
