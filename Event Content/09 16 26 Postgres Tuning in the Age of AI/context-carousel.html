Before you ask an AI to tune anything

Most installs aren't set up
to remember a slow night.

Under

No pg_stat_statements, no auto_explain, slow-query logging off.

Can't tell slow from slower. Can't answer "why" after the fact.

The four to turn on

pg_stat_statementswhich queries cost the most, over time
auto_explainsaves the actual plan when a query is slow
track_io_timingdisk wait vs CPU work (~1–5% overhead)
log_min_duration_statementlogs slow query text · start near 1s

Over

Log every statement, thresholds at 0–100 ms, auditing on everything.

Signal buried in volume. The same blindness from the other side.
pg_stat_statementsA running total. Tells you which query deserves your afternoon.
auto_explainA plan run by hand is a photograph. Fifty captured overnight are a film. Only the film shows the flip.
Ryan Booz's slides; setting names are Postgres config parameters. On auto_explain overhead, Ryan Booz: "Absolutely, it adds overhead" — yet customers where that was the real problem: zero.

What the plan pointed to

98% of the time was in
one subquery.

DATA PAGES READ · BEFORE (correlated subquery, re-run per row)
~193M
AFTER (materialized CTE: compute the set once, reuse it)
~1M
log scale · a page is an 8 KB block of table data, like a printed page Postgres has to read
1
Does it matter? 256 calls in 24h, already #3 by total runtime at 22%.
2
Is it always slow? No — four plan shapes, so capture the bad nights.
3
Where's the work? ~700 ms per loop × ~200 rows ≈ 200 s. Fix the loop, not the index list.
→
Next problem: the faster query still spilled its sort to disk. That's a memory (work_mem) fix, not a query fix.
Figures as shown and spoken in the talk (Blue Box demo DB); page counts rounded. MATERIALIZED forces Postgres (12+) to compute a CTE once instead of inlining it.

The human part that stays

Name the problem.
Then fence the agent in.

Query

The SQL asks for work it doesn't need.

fix: rewrite

Stats

Estimates are wrong, so the plan is wrong.

fix: ANALYZE, extended stats

Data

The work is real and the volume grew.

fix: less data, or accept it

Config

The plan is right; the memory isn't.

fix: work_mem, per role
