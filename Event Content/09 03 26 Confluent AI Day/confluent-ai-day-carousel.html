01 / 05 · The shift

Same AI, two postures

Request / Response
🛎️
Waits to be asked. Answers. Stops.
you → ask →
answer → done
Event-Driven
📹
Watches a live feed. Reacts the instant something happens.
event → react →
event → react → …
The unit changes from a request to an event — a fact that just happened. Receptionist vs. security guard.
02 / 05 · The stack

Three layers, one live stream

Kafka
The log. Every event written down, in order, and never thrown away — durable and replayable.
↓
Flink
The engine. Computes over that stream continuously — not on a nightly timer like a batch job.
↓
Streaming
Agent
The reflexes. Written in Flink SQL: reason → act → observe, over every new event — not once per API call.
Kafka = the log · Flink = the reflexesConfluent Cloud
03 / 05 · The payoff

You don't guess why.
You replay it.

Request-driven agent
Called once, then forgets. "Why did it do that?" → a shrug.
Streaming agent
Runs on the log. Replay the exact events it saw and watch the reasoning again. "Why?" has an answer.
Because Kafka never throws the stream away, you can rewind the decision — the real argument for event-driven AI isn't speed, it's auditability.
04 / 05 · The market

Everyone shipped an MCP layer in ~90 days

Confluent
Managed MCP Server — a governed way for agents to reach live data.
Snowflake
Bought Natoma (May 2026) for MCP governance.
Databricks
LakeFlow + real-time push into the same space.
MCP = "USB-C for AI tools" — one connector so any agent can call any tool.
The fight isn't whether to speak MCP. It's who governs it — access, redaction, and whether a tool's own description can be trusted.
