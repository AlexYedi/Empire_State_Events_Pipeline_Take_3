## Probe — measured ground truth
- **Topic crosswalk (YED-116) is DETERMINISTIC.** `signal.topics.source_record_id` = Empire `public.topic.notion_page_id` (de-hyphenated). **145/170 join 1:1**; id-match and normalized-name agree exactly on that set. 25 gtm-only topics (net-new inserts, finer themes), 13 Empire-only (unlinked), **2 Empire topics have NULL notion_page_id** (backfill). No fuzzy needed.
- **Dedup is barely a dedup.** Empire `public` already deduped (182 co / 232 person, **0 same-name collisions**). gtm entities **383/396 (96.7%) 1:1 by notion-id — zero false-merge on the strong key**. 13 leftovers = 12 "false splits" (same entity, different Notion page → recover by exact-name) + 1 genuinely new. **No fuzzy person-merge needed** (that was the only corruption path; person linkedin coverage only 65%, so fuzzy WOULD be dangerous — avoid it).
- **`notion_page_id` (the gating precondition) is healthy** — reliable 1:1 join key, with a hyphen-normalization gotcha + 2 topic backfills.
- **Event semantics gap (the real work).** Empire `public.event` (17) are **trend-radar market signals** (`kind='market'`), NOT the IRL speaker/host graph. The rich IRL graph (59 events / 629 edges: tagged_topic 202, works_at 200, speaker_at 160, host_of 65, attended 2) lives in the **Notion Events DB (71 events)** and was ingested into gtm's spine. Re-ingest into `public`: 429/629 edges map to `event_entity` after **role-vocab expansion**; 200 `works_at` → `public.person.company_id`.
- **Compute rewrite is SUBSTANTIAL.** The Empire prod DB's `public` has **no `relations` table, no `topic.cluster_id`, no `topic_cluster`**. Every CTE remaps `relations`→`event_entity`; cluster dimension must be built; outputs re-keyed to public ids; and the IRL event re-ingest must land FIRST — else the compute runs clean and emits a **structurally-valid-but-empty** snapshot (silent failure). The math survives; the substrate must be rebuilt.

## Pre-mortem — ranked failure modes → fixes
1. **[S1] Dedup false-merge → PII cross-attribution.** Fix: soft-merge only (`merged_into` tombstone, never DELETE), **merge-map written before the merge**, three-tier gate (exact-id→auto, strong-name→auto+map, fuzzy→human review), null-id ≠ match, hard-delete deferred past validation. *(Probe: strong keys make this near-zero risk; still use the machinery for the 12 splits + 1 new.)*
2. **[S1] In-place destructive on `public` = no rollback (no PITR).** Fix — **the central revision: EXPAND-CONTRACT.** Build the new graph in a parallel schema `canonical_v2`; never mutate `public`; validate; **atomic-swap** (rename / view-repoint). Rollback = swap back (sub-second, zero loss). **Removes the Pro/PITR requirement.**
3. **[S1] Topic mislinkage.** Fix: crosswalk committed as reviewed data (zero-orphan invariant); the 25/13/2 handled per-row with rationale.
4. **[S1/S2] Compute semantic drift (relations vs event_entity + `role`).** Fix: write the co-occurrence/role semantic mapping as a reviewable spec FIRST; **validate on invariants + a fresh reference impl on the event_entity model — NOT diff-vs-snapshot** (the old oracle is invalid post-rewrite).
5. **[S2] `signal_read` stranded mid-recompute** — solved free by expand-contract (blue-green).
6. **[S1] Decommission kills the oracle too early.** Fix: **cold logical export of the spine before any decommission**; "clean" = invariants passing (not diff); decommission = separate dated approval.
7. **[S2] Event re-ingest dupes/orphans.** Fix: upsert on notion_id (not insert); re-ingest AFTER dedup; explicit reviewed role-mapping table.

**Cross-cutting:** the validation oracle disappears (need invariants, not diff); `notion_page_id` is a SPOF across steps 1–3 (probe: healthy); the live pipeline writes to `public` during migration → **write-freeze + delta reconciliation**; **re-clone the Phantom Test Case DB fresh** before the real rehearsal; RLS deny-all + **no PII in logs/staging tables**, encrypted spine dump.
