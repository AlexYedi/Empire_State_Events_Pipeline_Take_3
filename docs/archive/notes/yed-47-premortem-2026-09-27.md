# YED-47 pre-mortem — Identity S1b-lite (2026-09-27)

**The question, asked before calling it done:** *It is 2026-10-27. The soft-merge and the resolution tier have been live for a month and retrieval is quietly wrong. What happened?* Written before the judge ran; each answer names what it changed in the build or why it was left alone.

| # | Failure imagined | Verdict | What changed |
|---|---|---|---|
| 1 | **Two different people with one name in the same manifest became one row.** The per-run cache keyed persons by name alone, so the second "Angie Jones" got the first one's id *right after* `note_ambiguous` had said a new row was being created. | **Real bug, pre-existing.** Caught by the new offline selftest before any live run. | Cache key is now `name|company_id` for persons (`substrate.py ensure_person`). |
| 2 | **A relevance recompute counted a merged entity's engagement twice** — the merge added the source's `engagement_count` to the target but left the source's own count in place. | **Real, in the first draft of this build.** | Merge sets the tombstone's `engagement_count` to 0; revert restores it from `engagement_moved`. `recompute_relevance.py` also skips tombstones outright. |
| 3 | **A merged topic kept showing in the hub's evolving-viewpoint panel.** The hub filters `relevance_score=gt.0`; a tombstone would keep its last score until the next recompute, and the recompute would re-score it. | **Real.** | Merge nulls `relevance_score` (nulling is always allowed by the ADR-9 guard); recompute skips tombstones. The hub needs no change. |
| 4 | **A writer outside `substrate.py` wrote to a tombstone.** `inbox_signal_write.py` resolves companies by exact name and bumps engagement; a tombstone with that exact name would take the hit. | **Real; one writer.** `backfill_people.py`, `spine_write.py`, `recompute_relevance.py` resolve by id, not name. | `inbox_signal_write.upsert_company` follows `metadata.merged_into` (5-hop cap). `identity_probe.py` reports `tombstones_with_edges` weekly as the detector for any writer added later. |
| 5 | **A colliding edge left on the tombstone loses information.** When the target already carries `(event, role)`, the source's copy stays on the tombstone rather than being deleted. | **Not a loss.** The target has the same edge by definition of the collision; the leftover is invisible to seed-resolved retrieval and is counted by the probe. Deleting it would violate ADR-4 D3 for no gain. | None. Recorded in the snapshot as `kept_on_source`. |
| 6 | **Tombstone chains or cycles.** A→B then B→A. | **Impossible by construction.** `merge` refuses a target that is itself a tombstone; `follow` fails loud past 5 hops and on a dangling target. | Selftest pins both refusals. |
| 7 | **`--revert` after the target moved on.** Later runs added edges to the target, or the target was merged again. | **Handled.** Revert restores only snapshot edges that still sit on the merge target, reports the rest as skipped, and never touches edges it did not move. | None. |
| 8 | **Ledger spam fires the DDL re-trigger from one ambiguity.** A re-run re-surfaces the same name ten times. | **Mostly cannot happen** (after the first run the created row matches exactly), but the probe counts DISTINCT `(table, name)` per window regardless, and `--dry-run` never writes the ledger. | Selftest pins both. |
| 9 | **The website-host rule matches too eagerly.** `aws.amazon.com` vs `amazon.com`. | **Conservative by design.** Hosts are compared exactly after stripping scheme/`www.`/path; subdomains are not folded, so that pair stays unresolved and surfaced. | None. |
| 10 | **The tier runs backwards** — a bare `AWS` arriving after `AWS (Amazon)` exists gets folded in. | **Out of spec, and deliberately not built.** Bare → qualified is surfaced to the ledger, never resolved. | Selftest pins it. |
| 11 | **`retrieve.py` builds a pack around a tombstone.** | **Real gap in the first draft.** The PRD's "both resolvers" means the producer *and* the read path. | `retrieve.resolve()` follows `merged_into` and de-duplicates a tombstone with its target. |

**What the pass did not cover, on purpose:** the DDL half (parked as YED-226 with the measured trigger); person fuzzy matching (never — ADR-4 D3); the hub's own queries (unchanged, and now correct by the null-score rule above).

**Live proof still owed to Alex:** the seven candidate pairs the probe lists (`AWS (Amazon)`→`AWS`, `LangChain (LangSmith)`→`LangChain`, `Agentic AI Foundation`→`Agentic AI Foundation (AAIF)`, `Angie Jones` ×2, three topic twins) were dry-run against the live graph in this session with zero writes. Every live merge is his call; `--revert` is the undo.
