Method: Husain & Shankar (error analysis → open coding → binary criteria → code graders first → model grader only when validated against Alex's labels), which is already how `output-evaluator` was built. Every number ships beside its do-nothing baseline (CLAUDE.md §5; `test_null_baseline.py`). Nothing below gates; everything flags.

## 5. Teaching layer

**What each eval type is, and why it matters here**

- **Example-based tests** (what the 540 selftest cases are): "input X gives output Y." They pin bugs you have already seen. Prior art: xUnit, Beck. Limit: they only know the bugs their author imagined, and here the author was the same model that wrote the code.
- **Mutation testing**: plant small bugs in the code on purpose (flip a comparison, delete a branch); a test suite that stays green against a planted bug was not testing that line. Artur's "mystery shopper for your tests." Prior art: DeMillo, Lipton & Sayward, "Hints on Test Data Selection" (1978); Meta's ACH, "Mutation-Guided LLM-based Test Generation" (arXiv 2501.12862, 2025), which Artur cited as "the Facebook paper." Why here: the PII guard is the one control with no backstop above it.
- **Property-based testing**: instead of examples you state a rule ("a refund never exceeds the payment"; for us, "a row containing an email never leaves the machine") and the tool generates thousands of inputs and shrinks any failure to the smallest case. Prior art: QuickCheck, Claessen & Hughes (2000); Hypothesis, MacIver. Why here: parsers over markdown that humans and models both write.
- **Architecture tests / fitness functions**: a test that asserts a structural rule ("only these three modules may write"), run on every build. Prior art: Ford, Parsons & Kua, *Building Evolutionary Architectures* (2017); tools ArchUnit, dependency-cruiser, import-linter.
- **Golden-set regression evals**: a frozen set of real inputs with labelled expected outputs, rerun whenever a prompt, skill or model changes. The eval is the spec ("evals are the new PRD", Foody). Method: error analysis and open coding before any rubric (Husain & Shankar); binary pass/fail per failure mode, never 1–5. Infante's four test types (functional, behavioral, performance, regression).
- **LLM-as-judge, validated**: a model grader is only a grader once its agreement with a human beats the do-nothing baseline. Prior art: Zheng et al., "Judging LLM-as-a-Judge with MT-Bench" (2023). Our own evidence both ways: output-evaluator 0.95 vs 0.65 (kept); the build judge κ 0.31 (demoted to flags-only).
- **Null baseline**: before trusting a metric, compute what it would read if the thing measured did nothing (majority-class baseline). The repo's own rule (YED-212), the reason the Gemini seat was removed.
- **pass@k / pass^k**: LLM outputs are non-deterministic, so run a case k times; pass@k = at least one success (capability), pass^k = all k succeed (reliability for invariants). Prior art: Chen et al., "Evaluating Large Language Models Trained on Code" (2021).
- **Trace-based evals**: grade the *recorder* (tool calls, models, errors per dispatch), not the agent's own summary — Artur's "asking the pilot, not reading the recorder." Prior art: OpenTelemetry GenAI semantic conventions; here, `dispatch_record.py`.

**Interview framings**

- On evals: "My pipeline's code gates are tested to the example level, so my next move is mutation and property testing on the PII guard, because the model wrote both the guard and its tests from one reading; the research layer gets golden-set regressions with code graders first and an LLM grader only once it beats the always-pass baseline."
- On the Visdom talk: "Of the ten layers, the two that transfer to an agentic content pipeline are the testing layers; the rest I either already run as policy — per-step tool scoping, orchestrate-the-process-free-the-step, a human as a node — or don't need at one operator."
- On judgment: "I removed a multi-model judge because its agreement number was the always-pass baseline, and kept a binary fact-checker because it beat that baseline by 30 points on my own labels."
